## 2. ROOT CAUSE ANALYSIS

### Why GitHub Push Protection Triggered:
The **API Key Intelligence** module evaluates detection engines against real-world credential formats. In commit `fe7f42d`, `backend/scripts/generate_api_key_dataset.py` generated 10,000 pseudo-random synthetic samples using exact cloud provider prefixes:
- AWS Access Keys (`AKIA[0-9A-Z]{16}`)
- Slack API tokens (`xoxb-[0-9]{11}-[0-9]{11}-[a-zA-Z0-9]{24}`)
- Twilio API keys (`SK[0-9a-fA-F]{32}`)
- Twilio Account SIDs (`AC[0-9a-fA-F]{32}`)
- Slack Webhook URLs (`https://hooks.slack.com/services/...`)
- Stripe live keys (`sk_live_...`)

GitHub applies identical regular expression rules in server-side push protection. Even though all samples were generated with Python `random.Random(42)`, GitHub's server-side scanner cannot verify whether a random string is active on a third-party API without sending traffic, so it rejected all matching patterns by default.
